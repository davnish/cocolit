    Architecture¶

    Cocolit counts coconut trees in satellite imagery. A user draws a box on a map, a YOLO11n model detects the trees inside it, and the result is drawn on the map and saved to a spatial database.

    This page describes how the system is built and deployed, how a request flows through it, and where to make changes.

    The deployment names keep their historical streamlit prefix; the frontend is no longer Streamlit.

    Frontend¶

    main.py is a FastAPI app with three jobs:

    • Serve the UI. static/index.html, static/style.css and static/js/app.js are mounted at /. The UI is vanilla JavaScript with Leaflet (maps), Turf.js (live area) and Leaflet.heat (heatmap). At build time, frontend.Dockerfile stamps a version into the JS/CSS URLs because Cloudflare caches those files for hours.
    • Run inference (POST /api/inference): validate the drawn shape, ask the router for predictions, save them and return them in EPSG:4326.
    • Statistics (GET /api/statistics): totals, a per-country table and heatmap points for every saved detection.

    It also exposes GET /healthz for Kubernetes probes and creates any missing database tables on startup.

    Drawing a box (static/js/app.js)¶

    The box tool uses pointer events, so mouse, touch and pen share one code path:

    1. Draw a box turns on draw mode and disables map panning and zooming, so a drag draws instead of moving the map.
    2. pointerdown records the start corner, and pointermove resizes the rectangle and updates a tooltip with the live area. The tooltip turns red above 0.5 km².
    3. pointerup finishes the box; a tap (under 10 px of movement) is ignored. Boxes over 0.5 km² are rejected in the browser. Otherwise the GeoJSON is posted to /api/inference.
    4. Each detected tree is drawn as a small circle. The status line above the map reports the result, or an error such as a rate limit (429) or an invalid box (422).

    Try another location cycles through SPOTS in app.js: dense coconut areas, each verified by running the model there, with village names from OpenStreetMap reverse geocoding.

    Local-first routing (src/inference_router.py)¶

    InferenceRouter.predict() decides where each request runs:

    • If fewer than INFERENCE_MAX_LOCAL requests are in flight locally (default 1), the request goes to the local inference service.
    • If local is already busy, it goes straight to the overflow URL (Cloud Run) instead of queueing.
    • If local fails with a connection error, a timeout, or a 502/503/504, the request is retried once on overflow. Other errors (for example 422, box too big) are raised and not retried.
    • Without an overflow URL, everything goes to local.

    The response header X-Inference-Backend: local|overflow shows which one served the request. Blocking work (HTTP and geopandas) runs in a thread via asyncio.to_thread, so one slow request doesn't freeze the frontend.

    Inference API¶

    src/api/inference.py exposes POST /predict (body: {xmin, ymin, xmax, ymax} in degrees) and GET /health. If INFERENCE_API_KEY is set (it is on Cloud Run), /predict requires a matching X-Api-Key header. Boxes that are too large or too small return 422.

    Pipeline (pipelines/inference.py)¶

    sequenceDiagram
    participant API as /predict
    participant P as InferencePipeline.run
    participant T as tiles.stream_patches
    participant G as Google tiles
    participant M as OnnxDetector

    API->>P: BBox (degrees)
    P->>P: validate (625 m² to 5 km²)
    P->>T: MosaicPlan for the box
    T->>G: fetch all tiles, 16 at a time, row by row
    loop each row of 640 px patches, as soon as its tiles have arrived
        T-->>P: patches (BGR, zero-padded at the edges)
        P->>M: patch
        M-->>P: boxes + confidence
        P->>P: box centres → EPSG:3857 metres
    end
    P-->>API: Predictions → GeoJSON FeatureCollection
    • Tiles (src/utils/tiles.py). MosaicPlan.for_bounds() works out which zoom-19 tiles cover the box and how they crop to the box exactly, using the same maths and rounding as the earlier rasvec GeoTIFF pipeline. _download() fetches and decodes tiles concurrently into one uint8 canvas. stream_patches() yields each row of 640 × 640 patches as soon as the tiles under it have landed, so the model starts while later tiles are still downloading. A missing tile (404) stays black; other HTTP errors fail the request.
    • Model (src/utils/detector.py). OnnxDetector runs models/best.onnx on onnxruntime and reproduces Ultralytics' pre- and post-processing: BGR→RGB, scale to 0–1, confidence above 0.25, NMS at IoU 0.7, boxes clipped to the patch. Its output matches Ultralytics exactly, without PyTorch in the image.
    • Output. Box centres are mapped from patch pixels to EPSG:3857 metres and returned as a GeoJSON FeatureCollection with a conf property. An empty result is an empty FeatureCollection, not an error.
    • Telemetry. Every stage (validate, detect, postprocess) is timed into bbox.timings and recorded as an OpenTelemetry span and histogram. tile_wait and model split the detect time between waiting for tiles and running the model. The calls are no-ops until src/telemetry.py is wired in.

    The model card and its AGPL-3.0 licence are in models/README.md.

    Performance¶

    scripts/benchmark_inference.py, Apple M1, identical detections before and after:

    Area Earlier (rasvec GeoTIFFs + Ultralytics) Now Peak RSS
    0.1 km² 0.38 s 0.21 s 263 MB
    1 km² 1.70 s 1.40 s 365 MB
    2.5 km² 4.52 s 3.08 s 525 MB
    4.9 km² 8.04 s 5.9 s 723 MB

    About 70% of the time is now the model itself. The next speed-ups are an INT8 model (1.8× faster but only 90–96% agreement with FP32, so it needs validating on labelled data), batched inference (which needs a dynamic-batch export from the original .pt weights), and a cache for repeated areas.

    Database¶

    PostGIS on CloudNativePG; tables are SQLModel classes in src/database/model.py, created on frontend startup.

    erDiagram
    BoundingBox ||--o{ Pred : contains
    BoundingBox ||--o{ Feedback : has
    Pred ||--o| Feedback : "low confidence"
    BoundingBox {
        int id PK
        string datetime
        geometry geometry "POLYGON, EPSG:3857"
    }
    Pred {
        int id PK
        int id_bbox FK
        float conf
        geometry geometry "POINT, EPSG:3857"
    }
    Feedback {
        int id PK
        int id_pred FK
        int id_bbox FK
        int yes
        int no
    }
    • preds_bbox_to_database() saves a box with all its trees. Trees with confidence below 0.3 also get a Feedback row, collecting candidates for review and retraining. A box with no trees is not stored, because the box is saved through its predictions.
    • read_data() loads every prediction and joins it with the country boundaries in data/countries/ in Python. That's fine at the current size; for larger data, move the aggregation into PostGIS (for example ST_Within with a GROUP BY).

    Deployment¶

    Kubernetes (Helm chart infra/charts/cocolit)¶

    Template Creates Enabled by
    inference_deployment.yaml, inference_service.yaml Inference pod and ClusterIP service (probes on /health, 1 Gi memory limit, no CPU limit) always
    streamlit_deployment.yaml, streamlit_service.yaml Frontend pod and service (probes on /healthz) always
    postgis_manifest.yaml, postgres-secret.yaml CloudNativePG cluster and credentials always (needs the CNPG operator)
    cloudflared_deployment.yaml Tunnel connector cloudflared.enabled
    inference_hpa.yaml Autoscaler inference.hpa.enabled (off for one node)
    streamlit_ingress.yaml, clusterissuer.yaml Traefik ingress and Let's Encrypt ingress.enabled, clusterIssuer.enabled (off behind the tunnel)
    • values.yaml holds the defaults.
    • values-laptop.yaml is the current single-node setup: k3s on Colima with locally built images (pullPolicy: Never), the tunnel on, ingress and cert-manager off, and a multi-arch PostGIS image.
    • Credentials come from a gitignored secrets-laptop.yaml. The tunnel token and the overflow URL and key are Kubernetes secrets created outside the chart.

    scripts/deploy_laptop.sh builds both images and runs helm upgrade --install, using a Helm container if helm isn't installed.

    Edge: Cloudflare¶

    • DNS for prithvilabs.com; the apex and www redirect to cocolit.prithvilabs.com.
    • The published tunnel route maps cocolit.prithvilabs.com to http://cocolit-streamlit-service.apps.svc.cluster.local:80.
    • A WAF rate-limiting rule on /api/inference allows 10 requests per 10 s per IP, then blocks for 10 s.

    Overflow: Cloud Run¶

    scripts/deploy_cloud_run.sh:

    • builds the inference image for amd64 with Cloud Build and pushes it to Artifact Registry, keeping the newest 2 images;
    • deploys it with 1 vCPU, 1 GiB, concurrency 1, min-instances 0, max-instances 2 and an API key;
    • writes the URL and key into the inference-overflow secret. Turn it on with --set overflow.enabled=true.

    Target node: Oracle Cloud¶

    infra/oci/ is OpenTofu for an Always Free Ampere A1 VM (arm64). It sets up a VCN that only allows SSH from one IP, a separate data volume mounted at k3s's storage path (so the database survives replacing the node), and k3s installed by cloud-init. retry-apply.sh retries until Oracle has capacity.

    Images¶

    Image Dockerfile Contents Size (compressed)

    Configuration¶

    Variable Service Purpose
    INFERENCE_URL frontend Local inference endpoint (set by the chart)
    INFERENCE_OVERFLOW_URL frontend Cloud Run /predict URL; unset = no overflow
    INFERENCE_API_KEY both Shared secret; the frontend sends it, inference requires it if set
    INFERENCE_MAX_LOCAL frontend Concurrent local requests before overflowing (default 1)
    POSTGRES_HOST, POSTGRES_DATABASE, POSTGRES_USERNAME, POSTGRES_PASSWORD frontend Database connection (or local_database with a full URL); unset = no database
    SMTP_FROMADDR, SMTP_TOADDRS, SMTP_USERNAME, SMTP_PASSWORD frontend Error emails
    ORT_THREADS inference onnxruntime intra-op threads (default: all cores)
    PORT inference Listen port (Cloud Run sets it; default 8000)
    OTEL_EXPORTER_OTLP_ENDPOINT both Enables OpenTelemetry export once wired in (otel.endpoint in the chart)

    configs/config.yml sets the model path (model.path) and the number of concurrent tile downloads (inference.tile_workers, default 16).

    Testing¶

    pytest tests --ignore=tests/integration      # unit tests, no network
pytest tests/integration                      # real tiles + model (network)
python -m scripts.benchmark_inference --sizes 0.1 0.5 1 2.5

    The unit tests cover:

    • tile placement, cropping and georeferencing against the rasvec formulas;
    • streaming patches matching the download-then-slice result;
    • conversion from pixels to map coordinates;
    • empty results;
    • GeoJSON parity with geopandas;
    • routing and overflow decisions;
    • API key checks and 422 responses.
